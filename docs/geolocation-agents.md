# SakuGIS 三 Agent 全球定位方案

## 目标与原则

输入可以是照片、自然语言查询，或两者组合。系统返回多个候选位置、地图
范围、证据、矛盾项和当前未校准的探索排序分数。统计置信度仍需独立验证集。

三个 Agent 是有明确输入输出的数据处理角色，共享结构化证据，不以自由
对话或多数投票决定坐标。视觉模型、大语言模型、OCR 和 GIS 查询都只是
Agent 可调用的工具；最终概率必须由独立验证集校准。

## 总体流程

```text
照片 / 查询文本
       │
       ▼
Agent 1：证据提取
EXIF、OCR、语言、标志、道路、建筑、自然环境
       │  Evidence[]
       ▼
Agent 2：候选生成 + GIS 查询规划
当前：千问宽召回 + 都市圈去重 + 地理多样性选择；
后续：H3 + GeoCLIP + 向量检索
       │  Candidate[] + SpatialConstraint[]
       ▼
GIS 验证器：Nominatim / Overpass / PostGIS
地点反查、OSM 标签半径约束、国家规则、数据覆盖率
       │  CandidateGISResult[]
       ▼
Agent 3：证据约束下的验证与重排
参考 GIS 结果、明确矛盾、输出独立证据复核分
       │
       ▼
确定性融合器：证据强度收缩 + GIS 覆盖率校正 + 硬冲突上限
       │
       ▼
GIS 图层：候选点、概率热力图、置信区域、证据与矛盾
```

## Agent 1：多模态证据提取

职责是描述和结构化“看到了什么”，不直接猜最终坐标。

- 本地解析 EXIF GPS、时间、焦距、方向和设备信息；将 EXIF 视作高价值但
  可伪造的证据。
- OCR 识别路牌、店名、域名、电话区号、车牌和交通线路；再做语言与文字
  系统识别。
- 识别左右通行、道路标线、交通标志、建筑材料、植被、地形、气候、海岸、
  山体和城市天际线等视觉线索。
- 对明确地标、品牌、交通运营商等实体进行检索和消歧。
- 每条证据记录来源、值、可靠度、适用地理尺度和相互矛盾关系。

建议的统一对象：

```json
{
  "kind": "driving_side",
  "value": "left",
  "reliability": 0.82,
  "source": "road_marking_model",
  "supports": ["JP", "GB", "AU", "NZ"],
  "contradicts": [],
  "provenance": "input-image"
}
```

## Agent 2：全球候选生成与查询规划

照片定位采用粗到细的混合方法，避免只依赖一个模型：

1. 在多个 H3 分辨率上进行国家/区域/城市级地理单元分类。
2. 使用 GeoCLIP 风格的连续 GPS 编码，检索全球候选坐标。
3. 用图像向量在有许可、带地理标签的参考库中做近邻检索。
4. 将 OCR 实体和 Agent 1 的地理约束转换成 PostGIS 空间过滤条件。
5. 合并多路结果并保留 20–100 个候选，交给 Agent 3 验证。

自然语言查询先转换为受约束的 `GeoQuery`，再编译为 GIS 操作，不允许模型
直接执行任意 SQL。例如“左侧通行、临海、附近有火山和葡萄园”可转换为：

```json
{
  "must": [
    {"field": "driving_side", "op": "eq", "value": "left"},
    {"layer": "coastline", "op": "within_km", "value": 20}
  ],
  "should": [
    {"layer": "volcano", "op": "within_km", "value": 80},
    {"layer": "vineyard", "op": "density_gte", "value": 0.15}
  ],
  "exclude": []
}
```

存储层首选 PostgreSQL + PostGIS + H3 + pgvector。PostGIS 负责拓扑、距离和
空间连接，H3 负责多尺度聚合，pgvector/HNSW 负责图像与文本近邻检索。

## Agent 3：候选验证、融合与置信度校准

对每个候选点或候选区域重新收集允许使用的参考证据，并进行成对验证：

- 比较 OCR 文本、语言、POI、道路方向和道路拓扑。
- 比较海岸线方位、地形高程、土地覆盖、气候及日照方向。
- 若许可允许，使用参考影像做图像匹配或候选—查询交叉编码验证。
- 明确记录支持证据和矛盾证据，避免只展示“正确理由”。

当前没有独立训练集，因此采用可审计的确定性融合：

```text
score(c) =
  0.20 · candidate_retrieval(c)
+ 0.35 · shrink_to_neutral(evidence_review(c), evidence_strength)
+ 0.45 · shrink_to_neutral(gis_score(c), gis_coverage)
- contradiction_penalty(c)
```

Agent 3 的 `evidence_score` 明确排除 GIS，避免同一 GIS 结果先进入模型分，
又被融合器重复计票。不可用 GIS 检查从 GIS 分数分母中排除，只降低
`gis_coverage`；融合时再把低覆盖率的 GIS 分数向中性值 0.5 收缩。国家反查
不一致会把最终排序上限设为 0.18，明确要求左侧通行但国家规则不一致时上限
为 0.42；用户明确提出的空间约束若得到真实 GIS 反证，单项不匹配时上限为
0.50；必需约束因服务不可用而无法核验时，每缺失一项也逐级限制最高分。
存在空间约束时，国家/城市反查只占 GIS 分的 25%，查询相关空间检查占 75%，
避免“坐标名称正确”掩盖“目标条件不成立”。相关证据按来源、可靠度
与适用地理尺度合并为证据强度，同内容证据先去重。报告会输出完整评分分解。

这套权重仍然只是 MVP 的探索排序。取得独立验证集后，应使用学习排序替换
固定权重，并用温度缩放或等距回归校准候选概率；共形预测用于生成达到目标
覆盖率的候选集合或地理半径。

界面不显示一个容易误导的总置信度，而分别显示：

- 国家概率，例如 0.78；
- 城市/区域概率，例如 0.55；
- 单个候选点概率，例如 0.31；
- 50%、80%、95% 覆盖半径或候选区域；
- 数据外分布告警和主要矛盾。

大语言模型的自我评价不得直接作为以上概率。

## 数据与合规边界

- OSM 标准瓦片只用于用户当前视口的交互显示。全球分析使用
  `planet.osm`/区域 extract、自建 PostGIS 或明确允许分析的数据服务。
- Google Map Tiles 仅用于合规地图可视化，不用于预取、索引、缓存建库、
  图像分析、机器解释或训练。
- 可评估 Wikimedia Commons 的地理标注媒体作为参考库，但必须逐文件保存
  作者、许可和署名要求。
- 其他街景或用户照片只在许可明确允许索引、派生嵌入和机器学习时接入。
- 默认在本机读取 EXIF；上传原图前提示用户。保存证据时记录来源、许可、
  时间和模型版本。

## 评估指标

- 地理误差中位数及 `Acc@1 km / 25 km / 200 km / 750 km`；
- 国家、一级行政区和城市准确率；
- NLL、Brier score、ECE 等概率校准指标；
- 置信区域实际覆盖率与平均面积/半径；
- 按洲、国家、城乡、昼夜、拍摄源和场景类型分组评估；
- 以地理单元切分训练/验证/测试集，并去除近重复图像，防止位置泄漏。

## 分阶段实现

### A：证据型 MVP

先实现 Agent 面板、照片导入、EXIF、OCR、语言/实体提取、自然语言
`GeoQuery`、OSM/PostGIS 查询和候选图层。这个阶段已经能形成可解释产品，
也能积累校准数据。

当前实现状态：

- 已完成 Agent 面板、照片与查询输入、macOS 本地元数据读取；
- 已完成基于千问 `qwen3.7-plus` 的三个顺序 Agent；
- 已完成结构化证据表、候选点/范围 QGIS 图层和双击定位；
- 已完成 API Key 的 macOS 钥匙串存储；
- 已完成 OSM Nominatim 地点反查和有界、缓存的 Overpass 标签约束；
- 已完成可选 PostGIS 后端，使用 `ST_Covers`、`ST_DWithin` 和
  `ST_Distance` 查询规范化 OSM 要素表；
- 已完成 GIS 检查表、GIS 分数和数据覆盖率，并将不可用数据按中性值处理；
- 已完成候选都市圈去重和最大边际相关式地理多样性选择；
- 已完成距离连续强度、证据强度收缩、GIS 覆盖率校正及国家硬冲突上限；
- 已修正跨日期变更线的 Overpass 查询框，并以线段而非仅顶点计算要素距离；
- 已完成中文 / English 运行时界面切换；
- 当前候选评分明确标记为未校准；
- 全球 OSM 数据库的部署、更多约束类型和独立校准数据集仍属于下一增量。

### B：全球视觉候选

接入 GeoCLIP/StreetCLIP 基线、H3 多尺度分类和许可影像向量库，输出
Top-K 候选与热力图。先评估公开预训练模型，再决定是否自建训练集。

### C：验证与可信度

加入候选成对验证、学习排序、矛盾处理、分组概率校准和共形置信区域。
完成跨地域压力测试后，再把模型服务与 QGIS 运行时一起纳入正式发布方案。

开发初期三个 Agent 可以是同一 Python 进程内的独立模块。参考库扩大后，
将 Agent 2/3 的索引与模型推理移到服务端，macOS App 保留编排、隐私控制和
GIS 可视化，避免过早拆成难以调试的微服务。
